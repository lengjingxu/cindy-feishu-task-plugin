# 最小公开协议方案（未实现、待审查）

目标是保留“扫码添加任意飞书应用、关联既有伙伴、任务自动受限执行、回报真实产物”。正式 0.1.120 的证据见 compatibility.md。以下是协议要求，不是可调用 API，也不是已获得的授权。

## 插件职责与凭据前置条件

插件 Node 负责飞书 SDK、短期 token、网络业务和长连接；逻辑页负责自己的账本、映射、队列、看板和回报校验。Host 保留安装批准、授权生命周期、文件过户、伙伴执行与回执。无旁路服务、私有 IPC、宿主数据库读取或普通消息替代。

正式文档允许 CLI 自管授权结果。插件可设计自己合法的安全存储，本阶段已实现 macOS Keychain + 账本随机命名空间，不能声称天然具备 Cindy 多账号隔离。合成凭据的本机保存、worker重启恢复与解除已验证；真实 Host 扫码验收及其他操作系统尚未完成。不能写临时目录/包目录代替持久化，也不能把 secret 回传沙箱或模型。

已有 /secrets + secretBindings 可用于用户输入凭据；它不是 SDK 新凭据写回。手动输入不能被悄悄当作扫码注册的替代流程。是否需要通用 Host 凭据写回，取决于最终选定的安全存储架构，**不将旧 saveMethods/settingsMethod 无条件列为平台必需改动**。

## 关键缺口一：Node 鉴权与已有文件票据组合

保留 uploadDir 过户规则与用户授权。最小通用增量是给已批准 Node 方法一个绑定当前 RPC/callId 的窄上传操作：接收原 dir_deposit token、限定目标 URL、普通表单字段，以及只经私有通道传递的短期 Bearer。Host 检查同插件/同调用、声明域名、文件数量/大小、一次性票据和取消。禁止重定向、自动重放、回传 token 或任意本机路径。

可以命名为通用“鉴权票据上传”，不要求旧 authenticatedFetch 原名上线；无需开放任意 Node→Host RPC，也无需将文件字节交给 Node。若未来公开协议能让 Host 安全持有动态应用凭据并交换 token，则可在该层完成，但须定义动态应用选择及身份绑定。

验收：原调用取消后不能上传、跨插件/跨调用票据拒绝、域名/重定向/文件范围拒绝、401/超时不自动重放、无 token 输出、真实文件读回与声明一致。

## 关键缺口二：真实伙伴执行与可信结束回执

扩展既有 targets 执行契约，不把正文包装成用户原话。必须提供：

- 功能探测：明确支持范围受限执行、收据查询与 settled；缺失时不发送。
- 提交：绑定已批准插件、目标伙伴、不可变业务范围、请求键及真实审核负责人。scope 不是真人原话，Auto 审核按真实来源处理。
- 受理回执：稳定 execution/binding ID、实际伙伴与 session ID、接收状态；重启后同键同内容取原收据，未知结果不重发。
- 输入与回报：仅原 execution/代次可关联当前工具调用，补充或取消保留真实来源，不接受插件自报 session 代替校验。
- 查询/取消：区分撤回、可能已开始、停止与 settled。只有可信 settled 才释放在途占位，不能推测 UI 或最终文字等于结束。
- 撤权/更新/切换账号：禁止新操作，保留已受理但结果未知的收据供核对；不伪称原生执行已停止。

无需开放伙伴历史、任意 session 控制或修改伙伴模型/权限。飞书读回、产物一致性和重复回报去重继续由插件实现。

验收：正式发布构建中验证绑定伙伴审核、重启同键查询、needs_input 保留、取消/settled 区分、原关联回报及循环两期自然执行。只用专用测试任务，不操作用户当前在途任务。

## 发布条件

安全凭据架构落地、两个缺口有正式公开支持、完成真实授权/文件/伙伴闭环后，才能确定完整插件 minCindyVersion。源码、模拟测试或支持检查入口均不能代替该验收。此方案不修改或发布 Core。
